# 项目工作流

## 开发流程
- **任务驱动**：所有代码变更必须关联一个具体的任务（Task）。
- **小步快跑**：鼓励将大的功能拆分为小的任务，每个任务完成后应及时提交。
- **测试先行**：对于核心逻辑（如 `dataService.js` 中的计算逻辑），应编写单元测试。

## 质量要求
- **测试覆盖率**：逻辑代码的单元测试覆盖率建议达到 80%。
- **代码审查**：提交前应检查是否符合 `code_styleguides` 中的规范。

## 提交规范
- **自动提交**：每个任务完成后，系统会提示提交代码。
- **记录摘要**：使用 Git Notes 或提交信息记录该任务的变更摘要，包含“做了什么”以及“为什么这么做”。

## 阶段验收
- **人工验证**：每个阶段（Phase）完成后，需根据 `workflow.md` 中的协议进行人工核对。
- **检查点**：阶段完成后创建 Git 标签或 Checkpoint 记录。
